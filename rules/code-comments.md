# 代码注释规范

注释只描述**代码做什么**——功能、行为、契约，简洁明了。

避免在注释里写：

- 对 `CLAUDE.md` / 路线图章节的引用（如「见 CLAUDE.md §2」）；
- 阶段、计划、待办（如「阶段 0 验收」「后期若需…再替换」）；
- 设计取舍的来龙去脉——它们属于项目规则，不属于代码功能；
- 句末句号——注释不加句号，用逗号或换行分隔短句；
- 冗余的装饰性分隔符——纯横线/星号围栏不带信息的注释一律删掉，包括：
  - 整行横线分隔带（如 `# -----------`、`# ============`、`// ----------`、`/* **** */`）；
  - 空行为留白而写的 `# ------ # 标题 # ------` 对称围栏；
  - 函数/分节标题靠横线来强调，而不是靠 docstring 或空行分隔。需要分节标题时，用一行简短的 `# 节标题` 注释即可，不加任何横线修饰。

设计取舍、阶段规划、架构决策统一放 `CLAUDE.md` 与 `rules/`。
代码注释要保持稳定：代码不变，注释含义就不应随时间漂移。

## 正例

```go
// Package env 提供 .env 文件加载：逐行解析 key=value 写入环境变量
package env
```

## 反例

```go
// Package env 提供最小化的 .env 加载。
// 设计取舍（见 CLAUDE.md §2）：手写逐行解析，不引入 godotenv。
// 后期若需更健壮的解析（多行值、变量插值等），再替换实现。
package env
```
